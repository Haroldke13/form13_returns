# ngrok Tunnel for Local App Access

This app can be exposed through ngrok with the `form14_ngrok` Docker sidecar in
`docker-compose.ngrok.yml`. The ngrok agent publishes a public HTTPS URL for the
local Flask container and exposes the local inspector on `127.0.0.1:4040`.

## What gets exposed

- Public app URL: generated by ngrok, for example `https://example.ngrok-free.app`.
- Local inspector: `http://127.0.0.1:4040`.
- Upstream app target: `https://web:8000` on the Docker Compose network.

The Flask app validates request hosts. The launcher reads the generated ngrok
hostname from the inspector API, writes it into `.env.ngrok` as
`NGROK_ALLOWED_HOSTS`, recreates the web container, and then tests the public URL.

## ngrok account setup

The current ngrok agent requires an authenticated account session. The Docker
agent does not provide a local Google device-code prompt. Use the ngrok dashboard:

1. Go to `https://dashboard.ngrok.com/signup`.
2. Sign in with Google or email.
3. Open `https://dashboard.ngrok.com/get-started/your-authtoken`.
4. Copy the authtoken into `.env.ngrok`.

Create the local env file:

```bash
cp .env.ngrok.example .env.ngrok
nano .env.ngrok
```

Minimum required value:

```env
NGROK_AUTHTOKEN=your-ngrok-authtoken
```

## Start and test

PostgreSQL deployment:

```bash
./scripts/ngrok_tunnel_up.sh postgres
```

Reuse the current app image:

```bash
./scripts/ngrok_tunnel_up.sh postgres --no-build
```

The script prints:

- `ngrok public URL`
- `ngrok inspector`

It also verifies that the public URL returns an expected HTTP status.

## Cloudflare CNAME use

For a stable Cloudflare CNAME, reserve a static ngrok domain or configure a
custom domain in ngrok, then add it to `.env.ngrok`:

```env
NGROK_URL=https://form14.example.com
NGROK_CLOUDFLARE_HOSTS=form14.example.com
```

In Cloudflare DNS, create a proxied or DNS-only CNAME from your chosen hostname
to the ngrok target shown by the ngrok dashboard. If you use a random
`ngrok-free.app` URL, the hostname can change after restart, so it is not a good
long-term CNAME target.

## Inspect traffic

Open the inspector locally:

```text
http://127.0.0.1:4040
```

The API endpoint used by the launcher is:

```bash
curl -s http://127.0.0.1:4040/api/tunnels
```

## Stop

```bash
docker compose --env-file .env.production --env-file .env.ngrok \
  -f docker-compose.prod.postgres.yml \
  -f docker-compose.ngrok.yml \
  stop ngrok
```
